# 浏览器内单文件 Markdown 编辑器

打开 `index.html` 即可使用（Chrome / Edge 等支持
[File System Access API](https://wicg.github.io/file-system-access/) 的浏览器）。
无构建步骤、无外部依赖，全部 HTML/CSS/JS 在一个文件里。

## 功能

### 支持 File System Access API 时

- **打开 / 保存 / 另存为**：首次写入时弹出浏览器授权；`Ctrl/⌘+S` 保存。
- **保存前冲突检测**：每次保存都重新读取磁盘文件，用 SHA-256 与「打开时（或上次成功
  保存时）」的内容摘要比较。发现外部修改后**暂停写入**，对话框并排展示磁盘版与草稿版，
  可选择：取消、用磁盘版替换草稿、仍用草稿覆盖（对话框期间磁盘再被改会要求二次确认）、
  另存为新文件。
- **草稿安全**：授权被撤销、读取/写入失败、冲突待解决或页面意外关闭时，未保存草稿连同
  文件句柄一起保留在 IndexedDB（库 `md-editor-drafts-v1`），并明确标出它所属的文件版本
  （基线摘要前 8 位 + 基线时间）。
- **重新授权不自动覆盖**：重新授权只读取并比对版本；磁盘较新时给出明确警示，必须由用户
  显式保存并在冲突对话框中选择后才会写入。
- 顶部草稿栏可恢复 / 重新授权 / 丢弃历史草稿。

### 不支持该 API 时（Firefox / Safari 等）

- 只能 **导入 .md/.txt** 并 **下载编辑结果副本**；页面显示黄色兼容提示。
- 状态栏文案明确区分：下载后提示「已下载一份 Markdown 副本；未写回任何原文件」，
  **不会**显示「已保存到原文件」。

## 设计要点

- 核心逻辑（会话状态、保存流程、冲突状态机、草稿持久化）不依赖 DOM，全部文件系统操作
  经过可替换的 `adapter`、草稿经过可替换的 `drafts` 存储，定义在
  `index.html` 的 `CORE-BEGIN/END` 标记之间。
- 每次保存尝试带递增 token（`gen`）：被取代的异步读取/写入即使迟到返回，也不会弹窗或
  改状态。
- 草稿仅在 `dirty` 时写入；保存成功（含另存为、采用磁盘版）后删除。

## 测试

```bash
node --test
```

14 个用例（Node 内置 test runner）。测试从 `index.html` 中提取核心代码在 `vm` 沙箱中
运行，注入内存版草稿存储和 `MockHandle`，可操纵：

- **权限丢失**：`file.permission = 'denied'` / 句柄 `revoked`，写入时抛
  `NotAllowedError`；
- **外部改写**：测试中直接改 `file.content`；
- **迟到读取**：`file.readGate` 为一个可控制的 Promise gate，先挂起保存 A，发起 B 后再
  放行 A，验证 A 被静默丢弃（不弹窗、不写入）；
- 文件句柄可替换（每次 picker 返回新的 `MockHandle`，通过 `isSameEntry` 识别同一文件）。

覆盖：正常保存、外部改写冲突及四种解决方式、撤权保留草稿、重新授权不自动覆盖、迟到
读取、写入失败重试、跨重启恢复、兼容模式导入/下载文案、再次打开恢复草稿。
